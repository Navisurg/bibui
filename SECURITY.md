# Security policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public issues, pull
requests or discussions.

Report them privately, in either of these ways:

- **GitHub private vulnerability reporting.** On
  [github.com/Navisurg/bibui](https://github.com/Navisurg/bibui), open the
  *Security* tab and choose *Report a vulnerability*. This is the preferred
  route: the report, the discussion and the fix stay in one private place.
- **Email** to dm@navisurgvision.com.

Tell us what you can of:

- the package and version affected (`Bibui`, `Bibui.Platform.Wayland`, ...);
- what the problem is and what an attacker could do with it;
- how to reproduce it: a small program, input file or steps;
- any fix or mitigation you have in mind.

## Who answers

bibui is maintained by Navisurg ApS, which holds its copyright. Reports are
read and answered by Navisurg ApS's maintainers.

## Supported versions

Only the latest release receives security fixes. A fix is released as a new
version, and older versions are not patched. Please check that the problem
is still present in the latest release before reporting it.

| Version         | Supported |
| --------------- | --------- |
| Latest release  | Yes       |
| Older releases  | No        |

## What to expect


- We aim to acknowledge your report within **5 working days**.
- We aim to give you a first assessment (whether we consider it a
  vulnerability, and how severe) within **15 working days**.
- We will keep you informed while we work on a fix, and agree with you when
  the issue is disclosed. We aim to release a fix within **90 days** of the
  report; if that is not possible, we will tell you why and what we expect.
- When the fix is released, we publish a security advisory on GitHub and
  credit you for the report, unless you would rather not be named.

bibui is maintained by a small team, so these are aims rather than
guarantees, but we take every report seriously.
